Table comments, read back from the Iceberg catalog
    bridge_query_table: Which tables each query touched. Grain: query x table x access type. Holds only what Trino measures per table (bytes and rows read). CPU and memory exist only per query and live in fact_query, so summing them through this table is always wrong.
    dim_table: Every table that appeared in at least one query. Grain: table. Derived from bridge_query_table, so a table nobody ever queried is not here.
    dim_team: Teams. Grain: team. Additional metadata, maintained outside Trino (org directory export).
    etl_batch: Load log. Grain: delivery batch. A batch is loaded again from the start until it is SUCCEEDED.
    fact_query: One row per completed Trino query (finished or failed). Grain: query. Key: (cluster_id, query_id). The only table with query-level measures (CPU, memory, totals). Sum them from this table or v_query_team alone: after a join to bridge_query_table every query appears once per table, and the sums would be multiplied.
    user_team_history: Which team each user belonged to, and when. Grain: user x membership interval. Intervals of one user never overlap, so a query maps to at most one team. Additional metadata (org directory export).
